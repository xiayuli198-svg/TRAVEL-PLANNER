05可靠性与诚实性设计

1. 断点续爬：进度按 OD 成员落盘

真爬 12306 是唯一会长时间联网的操作。进度不是记在内存里，而是逐对 OD 写进 SQLite： 开爬前记 running、做完记 done 并立即提交。断电、关窗口、进程被杀都能接着爬， 而且换过爬取范围也不会错位（旧实现按「第几对」切片，换列表就会切空、报「入库 0 趟」）。 更早的旧断点页面会如实提示「有旧断点残留」，不假装能精确续爬。

2. 数据诚实性：不编造查得到的实时信息

  • 路线库与 Ultra 的价格一律是公开攻略区间，明确标注「不是实时票价」；
  • 每条素材带 source / confidence / 口径日期，低可信度必须写明不确定在哪；
  • Ultra 校验器用正则挡掉车次号与精确时刻（写死在攻略里必然过期）；
  • 拷贝日会明确提示「不是当天真实车次」；排不出的行程按原因归类，不静默丢弃；
  • 世界数据不给机票价：只给大圆距离、预计飞行时间、时差与建议天数。

3. 配色与可读性

  • 填充色与文字色分开：--primary 只用于按钮底/边框，文字用更深的 --primary-ink（青绿当小字用只有 5.4 对比度，达标但费眼）；
  • 环境色只做色块（圆点/边框），绝不当字色；球面上的航线会提亮一档再画；
  • 原生下拉的选项显式写死深色字 + 白底（深色工具栏上的浅色字会被选项继承 → 白底白字）；
  • 对比度探针逐页签扫，含下拉选项专项与自检，当前 0 处不达标。

4. 不自动做事

爬取、写库、导入都必须由人点确认；后台任务可取消、有日志、有进度； 单进程同一时刻只允许一个爬取任务，避免风控与写冲突。

07已知限制与边界

限制说明与应对
时刻表是「参考」来自公开渠道的某一天数据，存在隔日开行/临时调图偏差； 拷贝日尤其只反映基准日。重要出行日建议真爬，买票前核对 12306。
需要 WebGL 与 Chromium 内核地图与地球模式依赖 WebGL；无 WebGL 时页面会明说原因而不是白屏， 室内点/动线等纯数据功能不受影响。
POI 坐标只用于示意城内点位来自高德检索，用于预览与示意图，不做导航； 查不到的名字记「未命中」，不猜坐标。
世界数据不含机票价世界航班票价必须实时查询，编一个数字没有意义； 因此地球模式只给距离/时间/时差/天数建议。
爬取受 12306 风控影响连续失败会触发长冷却并重建会话；失败的对记在账本里， 页面看得到，避免「以为爬完了」。
单进程单任务同一时刻只允许一个爬取任务；服务重启后内存里的任务信息消失， 但进度账本在数据库里，页面照样能续爬。
