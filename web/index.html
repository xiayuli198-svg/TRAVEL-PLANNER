    ROUTE BUILDER / 02

    把几座城市串成一条环线

    填想去的城市（至少两座），程序会在它们之间找一条当天可行的走法：可以闭合回到出发地，也可以单向走完。自由行会按停留天数把城市排开，避免同一天来回折返。

    环线有三套，先挑一套看 本页只放「京冀穷游 Ultra」（整条线、逐日花费）；另外两套在别的页签，点一下直接过去。

    环线 Ultra · 北京出发 / 河北出发的穷游环线

    这里是整条环线（几天走完、每天住哪花多少、哪里能省），不是单点走法。 小环线是省内/周边几站；大环线从北京/河北出发沿大动脉跨省走（≥8 天、≥6 城）， 比如「张家口 → 济南 → 南京 → 无锡 → 苏州 → 上海 → 杭州」，把二十多小时的直达拆成一段段坐下来。 价格为公开攻略区间、不是实时票价；每条都有来源与可信度，低可信度的写明了不确定在哪。 点开一条看逐日安排，带「看城内动线」的可以直接跳到那天的城市动线。

      DATA DESK / 05

      数据台：自动检查，一键补齐

      程序自己判断哪些日期缺数据、哪些是拷贝来的、哪些车次异常，列成清单；写库和真爬都要你点一下才执行， 真爬 12306 是后台任务，耗时取决于车次数和限速冷却；随时可以取消、断点续爬。

      直达

      数据可信度（体检 + 覆盖率）

      日期与来源

      来源分档很重要：导入和真爬是真实时刻表，拷贝只是同一天的复制品 —— 隔日开行、周末加开、临时调图都体现不出来，重要出行日建议真爬。

      日期车次数来源操作

      真爬某一天（后台任务，需确认）

      两种规模：定向爬取只爬跟目标城市相关的 OD（默认 320 对）， 日常补数据够用；全国爬取是 6006 对，耗时取决于车次数和限速冷却。 时刻表本身有隔日/调图偏差、只作参考，所以定向通常更划算。

      同一时刻只允许一个爬取任务。默认间隔 1 秒，遇限速自动降速并显示冷却倒计时，等待期间也可取消。进度逐对 OD 写进本地数据库：断电、关窗口、 进程被杀都不会丢 —— 回来把日期填成同一天、勾着「接着上次爬」再点开始，就只补没做完的那些 （已入库的车次也不会重复抓）。上面那张进度条来自数据库，不是内存里的任务。
