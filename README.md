# 使用之前需要一份个人的高德api用于仅有的详细联网查询，其余功能完全本地化，注意数据的真实性，无法反映及时的车次变化

# travel-planner — 国内大交通换乘规划（个人自用）

目标：输入出发地、目的地、日期、出发时间，一键输出**真实存在**的出行方案——
纯铁路 / 纯飞机 / 空铁联运，含换乘点的公交中转指引；支持大环线多站点逐日出行图，
以及在地图上按大区点城市、自动成环的「城市漫游」。

- 核心引擎：**RAPTOR**（round-based public transit routing）确定性算法，不做任何 LLM 幻觉数据
- 数据来源：12306 / 飞猪 / 高德公开接口（个人查询、限速使用）；购票一律跳转官方
- 城市资料：**239 座城市 · 10 个大区 · 26 条经典环线**（`src/travel_planner/data/city_catalog.json`）
- 存储：SQLite（`data/timetable.db` 时刻表 + `data/tourism.db` 城市旅游资料）
- 界面：命令行 + 本地 Web（http://127.0.0.1:8000），含立体中国地图

## 快速开始

```powershell
cd travel-planner
$env:PYTHONPATH = "src"

# ① 建库 + 车站
python -m travel_planner.cli init
python -m travel_planner.cli sync-stations        # 全国 3000+ 车站（12306 公开站名表）

# ② 获取时刻表（二选一）
#   A. 推荐：导入开源每日数据集（全国 1 万+ 车次，几分钟搞定，零风控风险）
#      下载 https://github.com/HerbertHe/cr-12306-train-info/releases 最新
#      train_detail_YYYYMMDD.json 到 data/import/ 后：
python scripts/import_dataset.py data/import/train_detail_20260617.json 2026-06-17
#   B. 自己爬：全国枢纽对枚举（耗时取决于车次数、网络和风控冷却；内置退避 + 断点续爬）
python -m travel_planner.cli crawl-date 2026-06-17
python -m travel_planner.cli crawl-date 2026-06-17 --resume   # 中断后续爬

# ② 配置高德 key（中转公交指引用，可选）
python -m travel_planner.cli set-amap-key 你的KEY   # 或环境变量 AMAP_KEY

# 配置飞猪航班查询凭证（可选；不要写进源码）
$env:FLIGGY_API_KEY = "你的飞猪API_KEY"
$env:FLIGGY_SIGN_SECRET = "你的飞猪SIGN_SECRET"

# ③ 规划（默认空铁联运 mixed；--mode rail / air / mixed）
python -m travel_planner.cli plan 丽江 上海 2026-06-17 --time 08:00 --max-transfers 2
python -m travel_planner.cli plan 北京 上海 2026-09-09 --mode mixed --links
python -m travel_planner.cli plan 北京 上海 2026-09-09 --mode air     # 纯飞机
python -m travel_planner.cli plan 北京 上海 2026-09-09 --mode rail    # 纯铁路
# 目标：最快（默认）/ 限时内最省（允许比最快晚 slack 小时）
python -m travel_planner.cli plan 昆明 上海 2026-06-17 --objective cheap --slack 4
# 单程游览：目标城市数、每个城市额外休整天数、全程天数上限
python -m travel_planner.cli plan 北京 拉萨 2026-06-17 --mode tour \
  --tour-city-count 5 --rest-days 1 --max-days 12
# 换乘口径已拆开显示：乘几趟 · 站内换乘 · 城市转场 · 预估票价
# （铁路为按里程估算「约¥」；飞机为飞猪真实票价）

# ④ 大环线多站点（核心场景，默认 mixed：每段自动选飞机/高铁最优）
python -m travel_planner.cli loop 2026-06-17 昆明 大理 丽江 昆明 --stays 2,2,0
python -m travel_planner.cli loop 2026-06-17 昆明 香格里拉 大理 丽江 昆明 --stays 1,2,2,0 --free-order
python -m travel_planner.cli loop 2026-06-17 昆明 大理 丽江 香格里拉 昆明 --objective cheap --slack 4
# 游览模式：每点玩半天串城 + 全程天数预算（超限自动给"删哪站"建议）
python -m travel_planner.cli loop 2026-06-17 昆明 大理 丽江 香格里拉 昆明 --stays 0,0,0,0 --max-days 6
#   --stays：0=纯中转，N=住N晚（默认 1）
# 游览环线可用 --tour-city-count、--rest-days；网页中“游览模式”会自动附加城市半日资料。

# ⑤ 地图漫游：按大区看城市 → 在地图上点成一串 → 自动成环排乘车表
python -m travel_planner.cli roam --regions                 # 看 10 个大区
python -m travel_planner.cli roam --region 江南              # 看某区城市的半日/一日建议
python -m travel_planner.cli roam --loops                    # 看 26 条经典环线
python -m travel_planner.cli roam --loop 大兴安岭环线          # 环线详情 + 每站怎么玩
python -m travel_planner.cli roam 2026-06-17 杭州 绍兴 宁波     # 排乘车表（默认回到起点）
python -m travel_planner.cli roam 2026-06-17 昆明 大理 丽江 迪庆 --open --mode rail

# ⑥ Web 界面（推荐日常使用）
scripts/run_web.ps1          # 或: python -m travel_planner.web
# 浏览器打开 http://127.0.0.1:8000 —— 单程规划 / 大环线 / 地图漫游 / 数据 四个页签

# 其他
python -m travel_planner.cli stations 丽江          # 查车站
python -m travel_planner.cli copy-date 2026-06-17 2026-06-18   # 时刻表复制到新日期
python scripts/maintain_data.py prepare 2026-06-18   # 自动选择最佳基线并准备日期
python scripts/maintain_data.py status              # 查看日期覆盖和推荐基线
python -m travel_planner.cli crawl-date 2026-06-17 --od BJP:SHH # 只补特定 OD 对
```

## 数据来源

| 来源 | 内容 | 用途 |
|---|---|---|
| 12306 station_name.js | 全国车站/三字码 | 车站表（无需登录） |
| 12306 leftTicket + queryTrainInfo | 车次整列停站 | 实时爬取（有风控，内置冷却/续爬） |
| [HerbertHe/cr-12306-train-info](https://github.com/HerbertHe/cr-12306-train-info) 每日数据集 | 全国约 1.1 万车次整列停站 | **推荐**的铁路基线数据，一键导入 |
| 飞猪官方 AI MCP（flyai.open.fliggy.com/mcp） | 某日某航线全部航班（航班号/航司/机场/起降时刻/经停） | 航班数据（免费，本地缓存；半官方端点，可能变动） |
| （备份方案）飞常准 AI 开放平台 ai.variflight.com | 权威航班时刻 | 个人注册 API key 后可接（接口已预留） |
| `data/airports_master.csv` | 常用中国大陆/港澳台民用机场主数据（IATA/ICAO/城市/坐标） | 机场城市解析与空铁换乘基础目录 |
| [DataV.GeoAtlas](https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json) 公开边界服务 | 全国省级轮廓 + 地级市中心点 | 立体中国地图与城市坐标（`scripts/fetch_china_geo.py` 抓取并简化后缓存在本地） |

说明：铁路数据集按「车次当日始发」假设导入天偏移，少数前日始发的过夜直通车可能整体偏移一天；正式出行请以 `crawl-date` 爬取的当天数据为准。航班数据按 航线×日期 缓存于 `flight_route_cache`，避免重复调用。购票一律跳转官方 12306/航司。

航班可以像铁路一样参与 `air` / `mixed` / 游览模式规划，但两者的数据形态不同：铁路是导入或爬取的全国车次表，航班时刻仍按查询城市、日期和航线动态调用后缓存；机场基础目录则可先运行 `python scripts/import_airports.py --replace` 导入。CSV 是个人规划用的基础目录，不宣称覆盖民航局全部机场；动态查询仍可补充未收录机场。

城市旅游资料单独保存在 `data/tourism.db`（可用 `TRAVEL_PLANNER_TOURISM_DB` 改路径），包含个人可编辑的推荐指数、简介、半日游建议和标签。游览模式的“玩半天”段会把对应城市资料展示在行程卡片中。

城市资料库现在是 239 座城市 / 10 个大区 / 26 条经典环线的规模，字段包括：评分、建议游览小时数与天数、最佳季节、标签、一句话简介、半日路线、一日路线、看点（带类型，如「苏州博物馆·博物馆」）、代表食物、交通枢纽标记、是否有铁路客运、提示。内置目录在 `src/travel_planner/data/city_catalog.json`，首次连接时写入 `data/tourism.db`；**数据库里的记录优先**，你在数据库里改过的内容不会被内置目录覆盖。

## 城市漫游（地图模式）

和「单程规划 / 大环线」同级的一种规划方式，区别只在于**怎么选出城市**：

1. 打开网页第 3 个页签「地图漫游」——一张低视角的立体中国地图（three.js / WebGL：Lambert 投影 + 地形抬升，青藏明显隆起，带光照与投影阴影）；
2. **页头先选出行方式**：🚄 公共交通 / 🚗 自驾 / 🔑 租车（见下节）；
3. 点顶部的大区（东北 / 华北 / 齐鲁 / 江南 / 华中 / 华南 / 西南 / 西北 / 青藏 / 港澳台），或直接点地图上的省份，视角会飞进这个区块，城市卡片带着配图挨个弹出来；
3. 鼠标停在卡片上：弹出这座城市的半日游建议、看点（博物馆会标 🏛）、评分、建议停留与最佳季节；无铁路的城市会标 ✈；
4. 点卡片：记作旅游城市 ①②③…，右下角列出顺序，可以上移/下移/移除、逐城设置「玩半天 / 住 N 晚 / 纯中转」，也可以一键「按路线排序」（最近邻 + 2-opt）；
5. 地图上还画着 26 条经典环线（大兴安岭环线、河西走廊环线、江南水乡环线…）。点环线：视角直接飞到这条环线；**跨大区的环线会先退到全国看清走向、再落到环线范围**，并展开它的说明与贴士；
6. 点「规划乘车表」：把这一串城市交给大环线引擎算真实车次，输出逐日乘车表 + 每座城市怎么玩 + 全程天数、游览时长、在途时长与估价，还会给「顺路可加」的周边城市建议。

地图用 **[three.js](https://threejs.org/)（WebGL）** 渲染：真实平行光 + 半球光、省界投影阴影、GPU 抗锯齿、跟随设备像素比（高 DPI 屏下也清晰）。库文件内置在 `web/vendor/three.module.min.js`（r160，654 KB），**不需要联网、不需要构建步骤**。省级轮廓用 `ExtrudeGeometry` 挤出成有厚度的板块，河流用 `TubeGeometry` 做出水面宽度，山脉沿脊线实例化 500 多个锥体，湖面用 `ShapeGeometry` 铺在对应海拔上。

交互（自研相机，不依赖库自带的控制器）：拖拽平移（抓住鼠标下的地面，跟手）、双指滑动平移 / 捏合或滚轮以光标为中心缩放、双击放大、右键上下拖动改俯角、⟲⟳ 按钮旋转视角、左下角还能调仰角；点「⛶ 全屏」让地图铺满整个窗口。地图默认就接近满屏（98vw × 94vh）。

地图上还叠了一层**手绘风格的「山川湖河」**（`web/data/china.nature.json`）：长江/黄河/珠江等 18 条河流、青海湖/鄱阳湖/洞庭湖等 13 个湖泊、天山/昆仑/喜马拉雅/秦岭/大兴安岭等 18 条山脉（按高度贴地，雪线山脉用白色三角符号）。不追求写实，只求一眼看出中国的地形骨架；想加一条河或一条山脉，直接编辑这个 JSON 即可（改完刷新页面，不需要重启服务）。

`Esc` 是逐层退出：攻略 → 全屏 → 环线说明 → 环线高亮 → 清空所选城市 → 返回全国视角（每次按都在左下角提示当前退到了哪一层）。

**选中城市之间的金色光带**：2-3 倍于视距自适应的发光管（外发光 + 实心光带 + 每个城市一圈金环和立柱 + 沿线流动的光点），全国视角下也看得很清楚；不再是一条 1px 细线。

**城市照片**：**239 座城市全部有白天实景照**，其中 **96 座「更适合晚上玩」的城市额外配了夜景照**（上海外滩、重庆洪崖洞、香港维港、西安大唐不夜城、长沙夜市、凤凰/丽江古城夜景、哈尔滨冰雪大世界…）。卡片按城市气质自动选白天或夜景图，夜游城市带 🌙 标记。照片由 `scripts/fetch_city_photos.py` 从 360 图片搜索抓取（Bing 兜底），统一裁成 960×640、压到 ~100 KB，来源记在 `web/img/cities/credits.json`，清单在 `photos.json`。**想换成自己的照片**：把图片命名成 `<城市名>.jpg`（夜景用 `<城市名>@night.jpg`）丢进 `web/img/cities/` 即可，脚本不会覆盖已存在的文件。

**完整旅游攻略**：每座城市的行程卡片底部都有「需要更多攻略？展开完整攻略」——点了才去 `/api/roam/city` 取（首屏不会因此变大），展开后是**逐日行程 + 交通 + 住宿 + 吃 + 预算 + 提示**的完整攻略；点城市名或右栏的 📖 按钮还会打开大图攻略弹层（含半日/一日路线、看点、实用信息、加入行程/地图定位）。

## 三种出行方式（页面顶部切换）

选城市的流程三种模式完全一样，区别只在「每段怎么走」：

| 模式 | 每段怎么算 | 结果里有什么 |
|---|---|---|
| 🚄 公共交通 | RAPTOR 查真实车次（火车 / 飞机 / 空铁联运） | 逐日乘车表、换乘指引、购票深链、票价估算 |
| 🚗 自驾 | **高德驾车路径规划**（真实里程 / 耗时 / 过路费，缓存进 `drive_route_cache`） | 逐日车程、单日驾驶时长与休息、油费、过路费、超长途拆分提醒 |
| 🔑 租车 | 同上 + 租车费用估算 | 日租区间 × 天数、异地还车费、保险、油费、过路费 → 总花费区间 + 6 家平台比价入口 |

- **自驾推荐按环线给**：26 条经典环线每条都有自驾资料（总里程 / 建议天数 / 真实公路编号与路名 / 最佳季节与封路期 / 加油与限速提醒 / 取还车城市与车型建议）。在地图左侧点任意环线即可看到，例如大兴安岭环线 2750 公里 / 12 天，走 G10 绥满高速 + G111 京加公路。
- **单日驾驶上限**：默认 ≤6.5 小时（可选 4/5/6.5/8），超过的段会明确提示「建议拆成两天或中途住一晚」，而不是硬排一天。
- **地图上的区分**：公共交通是金色光带，自驾/租车是**公路蓝**光带，自驾模式下还会在每段中点标出「D3 · 806km · 9小时6分」。
- **租车费用的数据现实**：国内租车平台（神州 / 一嗨 / 携程 / 飞猪 / 租租车）**都没有免费公开的报价 API**，要么登录要么商务合作；本项目按「城市档位（A 一线热门 / B 省会热门 / C 普通地级市 / D 偏远车少）× 车型（经济型 / SUV / 商务）」给**区间估算**，并附平台入口让你去查实时价。城市卡片在租车模式下会直接标出该城的 SUV 日租起价。
- CLI 同样支持：`python -m travel_planner.cli roam 2026-06-17 乌鲁木齐 吐鲁番 伊犁 阿勒泰 --drive --rental --car SUV`

> 打不开或一片空白时：地图上会显示红色提示框说明原因，点「重新加载地图」可重试。
> 如果提示「服务端还在跑旧版本代码」，说明网页是新的、后端进程还是旧的——重启
> `python -m travel_planner.web`（或 `scripts/run_web.ps1`）后刷新页面即可。

## 地球模式（第 4 个页签）

世界范围的规划视图，和「地图漫游」共用一套交互习惯，数据是独立的一份（`src/travel_planner/data/world_catalog.json`）：

- **世界城市卡**：87 座世界主要城市（东亚 / 东南亚 / 南亚中亚 / 中东 / 欧洲 / 北欧 / 北美 / 拉美 / 非洲 / 大洋洲 / 极地），每座都有真实照片（夜游城市自动用夜景照、带 🌙 标记）、评分、建议天数、半日/一日路线、看点、美食、提示，以及**完整多日攻略**（逐日行程 + 交通 + 住宿 + 吃 + 预算 + 提示）；
- **世界经典环线**：20 条，每条带一个**环境**（沙漠 / 海洋 / 极地 / 草原 / 雪山 / 古迹 / 雨林 / 高原 / 城市）与对应的 `env_color`，颜色跟着地貌走而不是随手挑浅色 ——
  - 陆地长线 14 条：欧亚经典（含西伯利亚大铁路）、欧洲西部、中东欧、北欧极光、地中海、中亚丝路、南亚金三角、东南亚海岛、日本黄金路线、中东奇迹、北美太平洋、南美印加、非洲草原、澳新；
  - **海上知名线路 3 条**：地中海邮轮环线、波罗的海与峡湾邮轮环线、南太平洋跳岛环线（`plan_mode: sea`）；
  - **南北极圈 3 条**：南极半岛航线（乌斯怀亚 ↔ 南极半岛，两站）、北极圈·斯瓦尔巴与极光带、格陵兰冰峡湾环线；
  每条给建议天数、总里程（大圆距离累计）、主要交通方式与实用建议；点一条 → 地球飞过去、画出整条线、把它经过的城市全部铺成卡片，并可一键放进路线；

- 保留原有的自转开关、全球视角与「高德 3D」按钮；`Esc` 先关弹层、再清空路线。

数据维护与抓图：`scripts/build_world_catalog.py`（合并 `data/world_content/*.json` → `world_catalog.json`）、`scripts/extend_world_loops.py`（给环线加环境色 + 补海上/极地环线与它们的新城市）、`scripts/extend_world_guides.py`（给这些新城市补看点/吃/提示/逐日攻略 —— 少了它 `guide` 是空的，城市卡点开只有简介）、`scripts/fetch_world_photos.py`（照片抓到 `web/img/world/`）。

## 环线 Ultra 版（「环线旅行」页签里的一个按钮）

现有路线库偏「单点走法 + 攻略」，适合单程；**整条环线出行**要看的是另一份东西：几天走完、每天住哪花多少、哪里能省。所以单开一份数据集，**不另开界面** —— 环线页签里点「环线 Ultra 版」按钮，普通环线结果让位，只留这份高质量环线清单，再点一次收起。

- 数据：`data/route_content/ultra_loops.json`（**64 条**，北京 29 / 河北 35，覆盖 12 个出发地：北京、石家庄、邯郸、保定、唐山、张家口、秦皇岛、衡水、承德、沧州、廊坊、邢台；3-19 天；口径 2026-09-25）；
- **分两档，页面可单独筛**（`scale` 字段）：
  - **小环线 34 条**（省内/周边几站，3-13 天，日均 128-245 元）；
  - **大环线 30 条**（跨省沿大动脉走，12-19 天、6-14 城，日均 240-450 元，含大交通）。判定标准就是用户给的那把尺子：「张家口到杭州直达 20 多小时，可以先到济南再到南京、无锡、苏州、上海，最后到杭州」——**把一条长直达拆成若干每段 2-8 小时的落地点，一路串下去，最后回到出发地**。构建器强制：大环线必须 ≥8 天、≥6 城、首尾闭环、写明走哪条大动脉（`hub_line`，如京沪线、京广线、京九线、陇海—兰新线、沪昆线、京哈线、杭深沿海线）；
- 每条含：`regions` / `transport` / 逐日 `itinerary`（哪天在哪、住哪、花多少）/ `highlights` / `save_tips`（怎么省）/ `comfort_tips`（怎么舒服点）/ `fit_for`（适合谁）/ `best_season` / `watch_out` / `source` / `source_url` / `confidence`（high / medium / low，低可信度的条目**写明不确定在哪**）；
- 接口：`GET /api/ultra?origin=&days_max=&budget_max=&q=&sort=value|budget|days|origin|scale&scale=large|small`、`GET /api/ultra/detail?id=`；页面按出发地 / 范围（大小环线）/ 最多天数 / 预算上限筛选，前两条默认展开逐日安排，详情里可一键跳到**出发城市的城内动线**；
- 口径：价格为公开攻略区间、**不是实时票价**，车次与门票以 12306 与景区官方渠道为准；
- 构建：子代理只写 `data/route_content/_staging/ultra_loops_*.json`，`python scripts/build_ultra_loops.py` 校验（含**车次号/时刻正则扫描**，扫描前会剥掉 `day`/`source`/URL，避免 `D1` 与网址片段误报）+ **增量合并**（先把已收录的 64 条读回来，再把暂存区并进去；只读暂存区会把上几批素材冲掉，这条踩过）→ `ultra_loops.json`，输入文件归档。

## 真爬（12306）与断点续爬

「数据台 → 真爬某一天」只在**你点确认之后**才启动，服务自己不会爬；同一时刻只允许一个任务。
两种规模：**定向爬取**（跟目标城市相关的 OD，默认最多 320 对）与**全国爬取**（6006 对）。请求按约 1 秒间隔起步；连接异常或 12306 风控时会退避冷却并逐步降速，因此实际耗时取决于车次数、网络和服务端限流，不承诺固定完成时间。数据台会显示当前请求间隔、冷却倒计时和逐对进度；断开或关闭后可用 `--resume` 接续。

**断电、关窗口、进程被杀都能接着爬** —— 进度不是记在内存里，而是**逐对 OD 写进本地数据库**：

- 每一对 OD 开爬前先记 `running`、做完记 `done` 并立刻落盘；所以断电时正在做的那一对，
  续爬会重新做它（没确认完成就该重来），而不是当成已完成跳过。
- 记账**按 OD 成员**，不按序号：全国爬到一半改「定向爬取」继续，或者换了目标城市，
  都不会错位跳空或重复爬（旧实现按序号切片，换列表就会切出空列表，跑完报「入库 0 趟」）。
- 已经入库的车次不会重复抓（靠 `schedules` 表去重），已发现的车次清单也是追加式落盘。
- 页面在「真爬」那张卡下面显示一条**来自数据库**的进度横幅：已完成 596/6006、剩余多少、停在哪、
  失败几对、已发现/已入库多少趟，带「接着爬剩下的 N 对」与「看逐对明细」两个按钮。
  数据台顶部那条「直达」导航也能一键跳到它。
- 更早版本留下的旧断点（只有「第几对」这种序号）页面会如实提示「有旧断点残留」：
  旧格式换过范围就会错位，所以下次爬取按 OD 重新核对一遍，不假装能精确续爬。

```powershell
python -m travel_planner.cli crawl-progress 2026-10-10 --rows 5   # 看某日进度与逐对明细
python -m travel_planner.cli crawl-date 2026-10-10 --resume        # 接着爬
```

## 路线库 → 我的行程（「数据台」页签）

路线库收的是「有人真走过、值得一说的走法」（`data/route_content/*.json`，合并校验后进
`src/travel_planner/data/route_catalog.json`）。每条都带 `source` / `confidence` / 口径日期，
**价格是公开攻略的区间、不是实时票价**；页面可以按城市、分类、巧思、单向/环线筛选与分页。

库里现有 **212 条**（含巧思 122 条），其中 **「分段串线」30 条**是这次按用户那把尺子补的：
**一条长途直达拆成 4-8 段、每段 2-8 小时，一路玩过去**（用户举的例子就是「北京/张家口到杭州直达 20 多小时，
不如济南 → 南京 → 无锡 → 苏州 → 上海 → 杭州」）。覆盖京沪、京广、京九、陇海—兰新、京昆/宝成—成昆、
沪昆、京哈/哈大、沿海、青甘/川西/滇西九条走向，北京 16 条 + 河北 14 条（石家庄/邯郸/保定/沧州/衡水/唐山/秦皇岛/张家口）。
写法约束由 `build_route_catalog.py` 强制：`segments` 按顺序排、`total_hours` ≈ 各段之和、
`name` 用「主题·起终点」、价格给区间并写口径日期、**不许写车次号与精确时刻**。
有意做成对条目（普速慢串 / 高铁快串、高铁 / 夜车硬卧），正好对应页面的性价比与巧思两种排序。

「排成行程」把参考路线交给本地时刻表引擎，排出逐日乘车表；「存进我的行程」把它存进
`data/trips.db`（`TRAVEL_PLANNER_TRIPS_DB` 可覆盖），可以反复看、比不同日期、导出 JSON。
数据台的「把整库排成行程并存档」是后台任务：**只读本地时刻表、不联网、不碰 12306**，可取消。

素材里的落脚点会被分成两类，页面直说区别：

* **铁路锚点**（有车站的城市）：用车次核实，给车次号、时刻与票价；
* **地面接驳点**（景区/小镇/口岸，如篁岭、黑马河、龙门石窟）：没有铁路站，
  按素材里那一段的时间与价格列出来，并标注「估算、需自查」，不假装有时刻表。

所以行程有三种结果：`铁路段已核实`、`含地面接驳`（partial，铁路段仍已核实）、`排不出`。

## 城内点位（只读预览，先不画地图）

城市攻略里的「看点」原本只是散文里的名字，没有坐标。这一步只干一件事：**按名单补坐标**。

* 名单 = 城市目录里 239 城约 900 个看点，**1 个名字 1 次请求**（高德关键词检索，不加
  types 过滤 —— 「中央大街」在高德那里是「地名地址;道路名」，按类型抓永远抓不到）；
* 校验三道：名字必须对得上、不能是配套点（地铁站/售票处/打卡点/××中心）、
  坐标要落在该省包围盒内且距市中心不超过 600 公里（酒泉代管敦煌约 380 公里，放得宽）；
* 查不到就记**未命中**（负缓存），不猜坐标；页面上把「返回的是什么、为什么没收」照实写出来；
* 州/盟名（伊犁、阿坝）高德不认，限定城市会返回空 → 自动全国查一遍，再靠省份 + 距离校验兜住。

```powershell
python scripts/fill_city_pois.py --dry-run        # 只看要查多少个名字
python scripts/fill_city_pois.py --limit 30       # 试跑 30 个
python scripts/fill_city_pois.py --delay 0.3      # 全量（约 900 次请求，几分钟，可随时中断续跑）
python scripts/fill_city_pois.py --report         # 覆盖率 + 命中/未命中抽样
```

数据落在 `data/poi.db`（`TRAVEL_PLANNER_POI_DB` 可覆盖），网页在「数据台 → 城内点位」只读预览。
**坐标只用于预览与示意图，不做导航**；高德数据只在本地自用缓存、不随工具分发
（要分发得换成 OSM / Wikidata 路线，那两个分别是 ODbL 署名与 CC0）。

首次全量结果：**897 个看点命中 896（99.9%）**，239/239 座城市都有点位、238 座全部补齐；
唯一未命中是**汉中油菜花海**——季节性花海没有单一点位（高德只有「皇塘油菜花」这类观花点），
按「宁缺勿错」留空，备注里记下了建议关键词。

覆盖率是怎么从 87.5% 走到 99.9% 的（都是查法问题，不是数据没有）：
**港澳台那 48 条**——(a) 省份包围盒里从来没有台湾/香港/澳门这三个框，点位一律被当成「查偏」丢掉；
(b) `city` 参数必须用**县市级全称**：`city=南投县` 查「日月潭」第一条就是它，而
`city=台湾` 返回空或内地同名点（北京门头沟也有个「日月潭」，距市中心 1743 公里，就是这么来的）。
自治州同理：伊犁→伊宁市、海西州→德令哈市、海北州→门源县。现在 `poi.CITY_SEATS` 管这件事，
关键词也可以写成「日月潭 @南投县」直接指定城市。
余下的条目由一份**名称校对**（`_staging/poi_fixes.json`，112 条：正式名 + 重查关键词 + 坐标 + 来源 + 置信度）
补上，用 `--apply-fixes` 并入；校对过的条目**不再被 `--revalidate` 二审**
（它们的正式名常写成「国立故宫博物院（台北故宫博物院）」，自动规则会误判成「名字对不上」）。

挑点规则踩过的坑（都写进了 `tests/test_poi.py`）：
「外滩」不能收成「外滩中心」、「豫园」不能收成「豫园(地铁站)」、「天涯海角」不能收成
「天涯海角(天鹿雅苑店)」；但「中央大街」在高德那里类型是「道路名」，名字完全一致时必须收。
换了规则之后不用把 900 个名字重查一遍：`--revalidate` 用存下来的名字/类型/坐标本地复判，
不达标的降级为未命中，再 `--misses-only` 只补这一批。

```powershell
python scripts\fill_city_pois.py --revalidate          # 用当前规则本地重审（不联网）
python scripts\fill_city_pois.py --misses-only         # 只补未命中的（换规则后补一遍）
python scripts\fill_city_pois.py --explain "阿坝/黄龙风景区"   # 排查某个名字为什么没收到
python scripts\fill_city_pois.py --apply-fixes <文件>   # 并入名称校对结果（带来源与置信度）
python scripts\fill_city_pools.py 北京 上海 --pages 3   # 给城内动线建 POI 池（4 类 × N 页/城）
```

## 城市停留动线（散文 → 带坐标的动线）

攻略里那几段散文本来就有顺序和时间（「9:00 地铁2号线中央大街站下，走到防洪纪念塔…」），
缺的只是「名字 → 坐标」。所以不做人工结构化，而是**自动对齐**：

1. **对齐**：拿城市 POI 池去散文里做**最长匹配**，命中顺序就是散文里的先后；
   对不上的名字保持纯文字（不猜坐标）。泛词（博物馆/公园/步行街）不进池子，免得散文里遍地都是。
2. **池子**：第一层是名单层已补好坐标的看点；第二层对**你真正打开的城市**按类型抓 4 页
   （风景名胜/科教文化/购物服务/体育休闲各 1 页 = 4 次请求）—— 步行街、老街、商圈这些
   在高德那里不算「景点」，只有第二层才捞得到。
3. **腿**：相邻两点之间按经纬度调高德公交/步行路径规划，拿到「几号线、在哪上、在哪下、几分钟」，
   落 `city_leg_cache`。这是**实时查询结果，不是时刻表**，页面上照原样标出来；查不到就写「没取到」。
4. **画出来**：按真实经纬度摆位输出一张 SVG **示意图**（不是地图、不做导航），
   线上标分钟数、点上标编号与名字。

实测（哈尔滨，池子 97 个点位）：D1/D2/D3 三天全部能画，对上 9 个点位；
D1：中央大街 →（22 分钟，含地铁）圣·索菲亚教堂 →（2 分钟步行）道里菜市场 →（45 分钟）太阳岛。

界面在「数据台 → 城市停留动线」；行程里的每一天也有「看这天的城内动线」按钮，
把那天的停留城市接到它的攻略动线上 —— 「怎么去」和「到了以后怎么玩」就串起来了。

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/guide/city?city=哈尔滨"            # 对齐结果（首次自动抓 4 页池子）
Invoke-RestMethod "http://127.0.0.1:8000/api/guide/day?city=哈尔滨&day=D1&live=true"  # 市内腿 + 示意图
```

## 交叉核对（维基百科 / 维基数据）

坐标补完之后用维基做了一遍独立核对（`scripts/verify_poi_coords.py`）：
按名字批量取维基条目的坐标（`prop=coordinates`，**50 个名字一次请求**，896 个名字约 20 次请求），
再和库里的高德坐标算大圆距离：

* 896 个点里 **362 个在维基上有同名条目**，距离**中位数 0.61 公里** —— 两个来源高度一致；
* 278 条 ≤2 公里（同一处地方）；66 条 2-20 公里、17 条 >20 公里，逐条看过之后分成三类：
  **同名撞车**（维基匹配到别处的同名条目，如「老外滩」撞上上海「外滩」、「台北故宫博物院」撞上北京「故宫博物院」）、
  **范围型**（沙漠/湖/山，维基给的是几何中心，我们给的是入口或镇子）、
  **真错**（点状地名却离维基很远）。

真错查出 6 条，全部是同一个翻车方式——**高德在城里找到了同名的别的东西，我们照单收了**：

| 看点 | 原来收到的是 | 改成 |
|---|---|---|
| 铜仁/梵净山 | 铜仁市区（0.8 公里） | 梵净山风景区（重查后与维基差 5.3 公里） |
| 上饶/三清山 | 「三清山水」（市区） | 三清山（28.9158,118.0644） |
| 海南州/青海湖 | 「青海湖广场」（共和县城） | 青海湖（37.0000,100.1333） |
| 遵义/茅台镇 | 遵义市区 | 茅台镇（27.8545,106.3675） |
| 韶关/丹霞山 | 韶关市区 | 丹霞山（25.0319,113.7461） |
| 凉山/西昌卫星发射中心 | 「西昌卫星发射中心子女学校」 | 发射场（28.2460,102.0266） |

顺带修了**挑点规则**里的一条：名字长一点通常是更完整（「三清山」→「三清山国家级旅游风景区」），
所以长度罚从 3 分/字降到 1 分/字（封顶 10 分），并给纯「自然地名」条目扣 25 分 —— 之前
「三清山」「梵净山」都是**地名录条目赢了真景区**，于是落到了城里。

还有一条要记着：**维基自己也会错**。维基百科「柳侯祠」的经度写成 108.4106（在河池境内），
实际在柳州市中心 109.4154 —— 差一个数字差一条河。所以批量 `--apply` 有风险，
更稳的是 `--suspects` 先看、人工确认后用 `--apply-only 城市/看点` 逐条改；
这条已按实际位置改回，并在备注里写明未采用维基坐标。

```powershell
python scripts\verify_poi_coords.py            # 全量交叉核对（约 20 次请求）
python scripts\verify_poi_coords.py --report   # 只看结果分布
python scripts\show_poi_check.py --triage      # 分成 同名撞车 / 范围型 / 疑似真错
python scripts\show_poi_check.py --suspects    # 只看「贴着市中心、真地方在远处」
python scripts\fill_city_pois.py --recheck     # 用当前规则定点重查这些疑点
python scripts\verify_poi_coords.py --apply-only 韶关/丹霞山   # 人工确认后逐条采用维基坐标
```

## 引擎特性

- **RAPTOR 确定性算法**：每轮 = 多坐一趟车；沿整条列车线扫描，正确性不依赖 LLM
- **城市级查询**：输「北京」自动合并全城车站（多起点/多终点），一次规划
- **换乘约束**：同站默认 10 分钟、同城异站默认 90 分钟（`transfer_rules` / `city_transfers` 表可改）
- **同车直通**：中途停车不重复计段
- **跨天正确**：过夜车按绝对分钟建模（如 D7 19:18→次日 07:25）
- **同城收尾**：到达站可为「同城接驳」目标（如到上海南 = 高铁到上海虹桥 + 约 90 分钟接驳）
- **真·同城判定**：同城异站接驳仅在两站站名都含城市名时启用（北京南↔北京西 ✓；县站如鹤庆↔大理 ✗）
- **空铁联运**：`--mode mixed`（默认）把航班与车次放进同一张图；机场↔铁路站同城接驳默认 150 分钟、机场同场中转 90 分钟
- **最快 / 限时内最省双目标**：`--objective fast|cheap`；cheap 用「时间-费用」帕累托标签算法，在允许比最快晚 slack 小时（默认 2）内求最省
- **票价估算**：铁路按里程×分席别费率估算（`约¥`；无坐标时用平均站距兜底，可选运行 `scripts/prewarm_coords.py` 预取全国车站坐标提高精度）；飞机显示飞猪真实票价
- **换乘口径拆开**：每方案显示「乘几趟 · 站内换乘几次 · 城市转场几次」，不再混在"换乘 N 次"里
- **绿皮省钱模式**：`--mode green`（Web 方式下拉可选）——只坐普速（K/T/Z/纯数字）+ 段价 ≤50 元的高铁/动车衔接（`--green-fare` 可调），极限省钱
- **单程游览模式**：`--mode tour`（每站玩半天/纯中转/住1晚，换乘不限）——沿最省串城链逐城玩过去（如 北京→呼和浩特→包头→西安→宝鸡→拉萨）；可选飞机参与，以「纯绿皮直达价×3」为闸门：超限按规则提示（建议弃飞机 / 参与飞机或绿皮卧铺）但仍列出方案
- **游览偏好**：可设置目标城市数与每个到达城市的额外休整天数；“玩半天”行程会附带 `data/tourism.db` 中的城市推荐指数、简介和半日建议
- **日期自动解锁**：查询的日期没有数据时，自动从最近有数据的日期复制时刻表（结果注明来源与调图风险）
- **全程日历显示**：环线/游览每段的「第 N 天」按行程起始日累计，不再各自从第 1 天开始
- **航班显示航司**：✈ 段附航司名（如 MU5100 东航）
- **游览模式**：环线各点统一"玩半天"串更多城市 + 全程天数预算，超限自动建议"删哪站可压到 N 天"
- **公交中转指引**：换乘点自动查询高德公交路径规划，地铁优先、纯公交标 🚌、深夜(23:00 后)提示打车（本地缓存；需 `set-amap-key`）
- **起点/终点接驳**：允许先坐地铁到同城其他站上车（如 上海南→虹桥火车站→G12），收尾同样可接驳到任意同城目标站
- **大环线多站点**：固定顺序逐段规划；`--free-order` 用 Held-Karp 对中间点做 TSP 寻优
- **日期自动推进**：停留天数 + 到发跨天自动计算下一段日期；缺数据的日期自动复制起始日时刻表
- **Pareto 过滤**：被支配方案（出发不更早、到达不更晚、换乘不多且至少一项更优）自动隐藏
- **绿皮省钱模式**：`--mode green`（Web 方式下拉可选）——只坐普速（K/T/Z/纯数字）+ 段价 ≤50 元的高铁/动车衔接（`--green-fare` 可调），极限省钱
- **购票深链**：`plan --links` 输出每段 12306 余票页链接（站名,三字码,日期已带好），购票在官方完成
- **爬取韧性**：连接异常会指数退避，识别到 12306 风控响应会延长冷却并降低请求频率；逐对失败可在数据台查看并续爬
- **一键体检**：`python scripts/data_health.py`（加 `--clean-junk` 可清理车次不足的调试日期）

## 城市漫游相关特性

- **真实照片**：239 城白天照 + 96 城夜景照（夜游城市自动用夜景图，卡片带 🌙）；缺图自动退回内置矢量海报
- **完整攻略**：每城一条多日攻略（逐日行程/交通/住宿/美食/预算/提示），按需加载，不拖慢首屏
- **金色光带**：选中序列用发光管道绘制，随视距自适应粗细，站点有光环与立柱，光点沿线流动

- **地图选城成环**：在地图上点出的城市序列直接交给大环线引擎，输出逐日乘车表；默认回到起点成环，可切换单程
- **停留方式两套来源**：按城市资料的建议天数自动推导（<1 天=玩半天、1-2 天=住 1 晚、2-3 天=住 2 晚…），也可以逐城手改
- **起点先玩**：起点城市设为「住 N 晚」= 出发前先停 N 天，出发日自动顺延并在结果里提示
- **每座城市怎么玩**：结果区按城市列出半日路线、一日路线、看点（带类型图标）、代表食物、最佳季节与实用提示
- **顺路可加**：按到所选路线的最短距离（<150 公里）推荐顺路城市，也给出全目录里评分最高但没选的城市
- **无铁路城市提醒**：舟山、甘孜、阿里、台湾各市等没有 12306 车次，会标 ✈ 并提示改用飞机/包车；黔东南、伊犁、迪庆这类州名会自动用驻地城市（凯里、伊宁、香格里拉）去查车次
- **大区一键飞行**：10 个大区（东北 / 华北 / 齐鲁 / 江南 / 华中 / 华南 / 西南 / 西北 / 青藏 / 港澳台）各自飞进对应区块并弹出城市卡片
- **经典环线图层**：26 条线路画在地图上，点击即飞到该环线；跨大区（如呼伦贝尔草原环线、三峡神农架环线）会先退到全国、再落到环线范围

## 已知限制（MVP）

- 只覆盖「爬取过的那一天」的时刻表；出行前先 `crawl-date`。全国爬取可能持续较久，耗时受车次数、网络及服务端限流影响；可定向爬取并在中断后续爬
- 爬取覆盖 = 主要枢纽城市间车次（凡经过 ≥2 个枢纽的车次会整列入库，含非枢纽中间站）
- 未包含：余票、票价、12306 登录（购票请跳官方）
